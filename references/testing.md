# 验证 3.2，而不是替它证明成功

## 三类状态分别记录

1. **文本/结构检查**：引用、事件、时长、状态链和脚本字段正确。
2. **生成观察**：实际看过哪些视频、完整片段还是抽帧、是否听了声音。
3. **用户验收**：用户是否认可画风、剧情和镜头；不能用自检冒充认可。

未生成的视频填“待实测”，不填通过。研究别人的成片不等于V3已生成成功。

## 必测情形

| 情形 | 期望行为 | 失败判据 |
|---|---|---|
| 单图已放下物件 | 从释放后继续，或说明需不同首帧 | 再次凭空生成手中同物件 |
| 单图要求360度环绕 | 标出未知背面，补依据或说明推断风险 | 承诺空间完全不变且无证据 |
| 九镜交接 | 数量/归属逐镜更新，远镜仍保持 | 交出后下一镜无因取回 |
| 正反打 | 对照世界位置与轴侧，跨轴有可读过渡 | 为保持屏幕左右而交换真实座位 |
| 黑红手绘三徒弟 | 原画风、三个可辨角色和化形因果都保留 | 真人化、只剩烟雾或缺角色 |
| 群像 | 角色职责、视线和不同节奏，数量符合剧情 | 复制人脸/错误增减人数/机械同步 |
| 5秒大动作链 | 保留关键事件，提出分段或延长 | 把全部动作和长对白压进5秒 |
| 新参考顺序 | 全文、绑定表、角色映射同步更新 | 旧编号残留或内部UUID假绑定 |
| 只借色调/构图 | 不把参考直接作为成片帧 | 首帧复制用户禁止使用的画面 |
| 品牌单图 | 产品结构和真实光源优先 | 为炫技换产品/穿墙/虚构采光 |
| 延续与延长 | 故事续段可切镜，无缝延长需实际尾段 | 没有源视频却声称已绑定延长 |
| 4K请求 | 分清当前网页与API能力 | 用未支持API字段许诺4K输出 |

## 结构化账本与检查器

3.2.2 的 `scripts/test_prompt_template.py` 检查两个已填示例及缺栏、空栏、占位符、英文字母、显式自由格式等反例；`scripts/test_prompt_html.py` 验证默认不完整正文会阻止建页。这些测试不衡量模型的剧情还原能力。

人工另查：只要静帧不强加视频；九栏不扩成九镜；每段独立完整；时间连续并覆盖总时长；台词在时间轴与声音栏归属一致且不重复。模板来源应区分字节官方、平台教程与社区案例；只读到文字时不得标记成片已验收。

可选 JSON：`duration`、`shot_count`、`mode`（edited/single_take/independent）、`reference_ids`、`initial_state`、`required_facts`、`shots`。镜头含 `id/start/end/source_facts/refs/pre/post/changes/transition/camera`。物件状态键如 `lamp.holder`、`lamp.count`；变化项含 `key/from/to/event`。最后一镜 `transition=end`。

`scripts/check_plan.py 账本.json` 验证声明的时段覆盖、数量、引用、来源覆盖、前后状态和有事件的变化；不推断“event”文字真假，不证明反打合法、身体比例正确或提示词正文与账本相符。结构化检查通过后仍须人工核对正文与资产。

`scripts/test_check_plan.py` 包含对照和故意错误：间隙、重叠、重置道具、漏变化、漏来源、错参考、一镜到底偷切、漏摄影机终点。它是工具单元测试，不是语言模型行为评测。

## 实际 A/B 测试（用户授权生成后）

选同一张图、同一镜号和故事；保留旧提示词作为A，新版为B。固定模型/入口/参考/时长/画幅/分辨率/音频；有种子且入口真实支持时记录，不能保证完全确定性。用户授权预算内尽量每组多次生成，分别记任务ID与失败，不只挑最好一条。

先测高风险小片段：交接、反打、明显位移、手绘保真；过关后才扩九镜。更换素材/模型与改提示词同时进行会混淆归因，确需调整时另开版本并说明。

先过硬门槛：故事核心、身份、必要角色、产品几何、道具守恒、空间和轴线、动作完成、切点、音画。关键失败不能被“质感好”平均掉。再评价构图、表演、光影、节奏，记录具体时段与观察。

对交接和跨轴需看完整事件窗口及前后镜；三帧截图不足以确认。未知写未知。只修失败维度，再复查受影响的后续镜；保留原始输出，不默默删失败样片提高成功率。

允许声称的结论：本组样本中哪项更稳、失败几次、在哪些条件下。禁止从少量样本宣称普遍解决九镜连续性或模型质感。
